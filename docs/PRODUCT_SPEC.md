## Product concept

An open-source, evidence-first document assistant for HR teams. Users add approved HR policy files, ask questions in plain language, and get **verifiable answers with exact source citations**. They can tell internal policy apart from law, inspect source passages, and discover when the answer is missing, outdated, or contradictory. Not legal advice or a definitive compliance tool. No AI-invented HR rules.

**Core differentiator:** traceable claims + source versioning + abstention + hybrid search + realistic offline demo without paid API keys. Build an actual product UI, not the default chatbot tutorial.

## Behavior and retrieval

- MVP must work fully offline after dependencies/models are installed, using an **extractive answer mode**: show the top directly relevant source paragraphs with their document/page metadata and do not impersonate an LLM-generated explanation. Optional grounded natural language mode via configured local Ollama/provider only if available.
- Chunk policy documents at section/page-aware boundaries. Persist document ID, revision, section/page, chunk ID and ingestion timestamp.
- Query flow: validate question -> apply document category/permission filters -> BM25 + dense retrieval -> weighted fusion (e.g. RRF) -> optional rerank -> evidence quality threshold -> answer/evidence or explicit abstention.
- Cite each claim with stable source identifiers; snippets must correspond exactly to stored extracted text. Prevent a document's instructions from overriding system rules (prompt injection defense); never execute arbitrary uploaded content.
- Detect simple contradictory evidence: when sources disagree, show both with effective dates rather than choosing a fabricated authority.
- Handle no document, failed parsing, duplicate upload, unsupported extension, expired/superseded source, no relevant result, and Qdrant downtime gracefully.
- Protect file uploads with size caps, safe names, MIME checks where possible and metadata validation. Do not log private document contents. Show delete-all-data action in demo. If implementing multi-user access, enforce tenant isolation in DB and retrieval filters, not merely UI.
